# 部署前安全清单

> 在把任何 AI 工具接入真实工业项目之前，逐条核对。这些原则来自工业界实践（参考 awesome-plc-ai 等），不是本项目的原创。

## 核心警告

**PLC/工业代码驱动机器。** 以下任何工具都**不能免除**评审、静态分析、仿真与现场调试。安全功能属于硬件（安全继电器 / 安全 PLC），硬联锁在电气或气动回路里。**任何未经检查的 AI 输出都不应下发到运行中的控制器。**

---

## 六条清单

### 1. 只读优先（Read-only first）

- [ ] 先用**只读**的桥接器，让 AI 只做总结、交叉引用、文档化，**再**考虑任何写入能力。
- [ ] 确认当前接入方式没有任何写操作的路径。

### 2. 强制验证门（Compile / Validation gate）

- [ ] 任何改动在「通过验证」之前都不算完成。
- [ ] 对程序类改动：编译必须干净，警告视为错误。
- [ ] 对分析类改动：阈值与规则必须经过领域专家确认。

### 3. 优先 diff / 提案，而非直接写（Prefer diff over write）

- [ ] 工具应产出**可审批的变更**，而非直接写入。
- [ ] 具备 dry-run（试运行）与 rollback（回滚）能力。
- [ ] 写操作需人工确认后才执行。

### 4. 仿真先于硬件（Simulate before hardware）

- [ ] 先用虚拟控制器 / 仿真环境验证，再读取返回值与预期对比。
- [ ] 本仓库的 `SimulationAdapter` 即为此目的提供。

### 5. 数据留在本地（Keep the data in）

- [ ] 涉及真实项目文件时，on-premises（本地部署）是采购要求。
- [ ] 不把真实点位表、工艺参数、历史数据上传到云端。

### 6. 查许可证，而非看星标（Check the licence）

- [ ] 只分发二进制、无开源许可证的仓库不是开源生态。
- [ ] 复用前确认许可证类型（开源 / 可读但保留权利 / 商业）。

---

## 本项目适用的边界

本仓库是**只读**框架，天然满足第 1、2 条（无写操作、规则需人工确认）。但接入真实 DCS 前，仍需由工业自动化与安全专业人员完成：

- [ ] 网络分段与数据二极管验证
- [ ] OPC UA 只读权限配置
- [ ] 审计日志开启
- [ ] 操作员培训与应急预案

---

> 记住：**AI 输出是草稿，不是权威。人在回路，永远保留最终决定权。**
